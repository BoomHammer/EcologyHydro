# M3 工程试算与验收

执行日期：2026-10-09。工程闭环与本次性能验收通过；科学精度尚未验证。使用锁定的 InVEST 3.20.2 官方 Annual Water Yield 实现，未替换模型公式。

## 运行口径

采用 M2 已保存的 250 m WGS84 Albers 等积网格、土壤、年度气候和非重叠分区。先运行唐乃亥子流域，再运行全部 11 站控制区域。全域两套地类均使用 2019 年、降水 `prec`、固定工程假设 Z=5，不按观测选择参数。并发测试使用 2019—2022 年唐乃亥任务；没有使用 2023 年验证观测。

M2 的参数先验、土壤深度代理、气候及水文修正近似继续有效，详见 [M2 验收记录](M2_ACCEPTANCE.md)。自然产水与受调控实测径流不是完全一致的物理口径，人工修正列保留为空。当前试算明显高估观测，例如 Copernicus 唐乃亥为 813.019 亿 m³，实测为 310.3 亿 m³；不得将本次结果作为精度验收或精细分类优于现成产品的证据。M4 应先复核降水/PET、参数来源和汇水区近似，再开展预先登记的率定。

## 可复现命令

在项目根目录 PowerShell 执行：

```powershell
# 单年全域；默认 2019、Copernicus、Z=5。
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 python -m ecologyhydro simulate

# 指定子流域或另一套地类；--force 强制重新计算。
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 python -m ecologyhydro simulate --scope tangnaihai --year 2020 --z 5
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 python -m ecologyhydro simulate --landcover fine

# 完整工程套件，包括 1、2、4 并发基准。
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 python -m ecologyhydro trial

# 从实际运行清单校验并汇总报告。
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 python scripts/report_m3.py
```

`simulate` 只接受配置中的校准年份，避免工程试跑使用留出验证年。`trial` 固定上述工程方案；`--skip-benchmark` 可省略并发测试，但不能据此替代完整性能验收。公共配置中的正式输入和率定 Z 保持未冻结状态，M3 从 `project/cache/m2/latest.json` 解析工程输入。

## 保留的中间数据与追溯

- `project/cache/m3/scopes/`：子流域/全域边界和裁剪分区。
- `project/cache/m3/masked/`：分别缓存土壤、气候、地类的范围裁剪及掩膜结果。官方模型会重分类边界外包矩形内的地类，因此流域外统一设为 NoData，流域内缺失或未定义类别直接拒绝运行。更换地类或气候不会重复处理未变的静态输入。
- `project/cache/m3/completed/`：包含输入、参数、版本和实现指纹的成功任务索引。复用前核对输出 SHA256；输出缺失或被修改不能作为成功结果跳过。
- `project/m3/<batch_id>/<run_id>/`：每次请求独立目录，保存配置及输入快照、模型日志、模型输出、分区与测站表、核验记录、阶段耗时和资源记录。复用请求显式引用原结果，失败重试生成新目录；原失败证据保留。
- `project/m3/latest_suite.json` 与 `suite_*.json`：最近套件及历史套件清单。
- `project/m3/report/`：`stations_2019.csv`（两套方案共 22 行）、`performance.csv`、`summary.json`、`report.md`。

这些大型运行产物沿用项目忽略规则，不纳入 Git；本验收文档保留关键数字。M2 共享预处理不计入本次单模型耗时，其成本见 M2 验收记录。

## 正确性核验

像元体积按 `Σ(产水深 mm × 像元面积 m² / 1000)` 累加，以分区归属表汇总嵌套站点，每站每分区只计一次。要求控制区域内所有像元有效，检查产水与蒸散之和等于降水，并与官方分区 `wyield_vol` 交叉核对。

本次最大水量平衡误差为 0.0001220703125 mm；官方分区体积与像元积分的最大相对差为 4.3700×10⁻⁷，低于 10⁻⁵ 的验收容差。唐乃亥单独运行与全域运行的该站体积完全一致；1、2、4 并发下同年结果体积差为 0 m³。

41 项测试通过，包括官方 AWY 合成数据集成、单位换算、NoData/负值拒绝、嵌套分区去重、观测异常区分、参数映射、结果损坏检测，以及实际子进程的超时/内存超限终止。Python 代码通过 Ruff 检查和格式检查。

## 性能实测

下表是本机实际执行值，包含调度及当次输入准备、官方模型、汇总与写盘。峰值内存为调度器及其子进程树 RSS 采样值，每 0.5 秒采样；磁盘每 2 秒采样，不能视为连续测量的精确最大值。单任务另存 CPU 时间、利用率和工作目录占用。

| 任务 | 任务数 | 并发 | 批次耗时 秒 | 进程树峰值 MiB |
| --- | ---: | ---: | ---: | ---: |
| Copernicus 全域 2019 首次计算 | 1 | 1 | 60.28 | 446.3 |
| 精细分类全域 2019 首次计算 | 1 | 1 | 47.92 | 444.7 |
| Copernicus 全域结果复用 | 1 | 1 | 3.11 | 151.6 |
| 唐乃亥 2019—2022 | 4 | 1 | 43.47 | 478.1 |
| 唐乃亥 2019—2022 | 4 | 2 | 22.64 | 859.1 |
| 唐乃亥 2019—2022 | 4 | 4 | 11.33 | 1321.0 |

独立首次唐乃亥试跑耗时约 24.2 秒；套件的 smoke 记录为复用请求（2.61 秒），不能误报为首次模型耗时。并发比较在共享输入准备完成后，均强制执行模型，没有使用结果缓存。4 并发相对串行吞吐约提升 3.84 倍。全域 Copernicus 的官方模型阶段为 38.52 秒，当次输入准备为 14.61 秒；工作目录约 318.6 MiB，其中模型中间文件约 172.3 MiB。首次全域试跑期间存在其他测试活动，因此这些值是工程实测，不是隔离性能实验的保证值。

两套全域运行均满足 12 小时和 24 GB 预算。每个模型内部串行执行，数值库每进程 1 线程，避免嵌套并发。代表性小流域测试以 4 并发最快，但尚未实测多个全域任务同时运行，常规资源配置继续保留 `config.yaml` 的 2 任务上限。大规模率定前可用同一调度器补充全域并发吞吐验证；不将小流域加速比直接外推。超时或内存超限会终止工作进程树并保存失败原因，不算验收成功。
