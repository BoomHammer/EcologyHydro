# 2011—2024 三产品交叉参数实验

更新：2026-10-11。本文是当前实验协议；旧长序列与月试点报告保留历史结果，不沿用其年份规则。
唯一执行配方为 [landcover_comparison.yaml](../config/landcover_comparison.yaml)。

## 1. 数据与时期

用户新表实际名为 `*2011-2024.csv`，不是 2011—2014。读取列名而非按列位置截取；1998—2010 的旧列不参与本次实验。

| 时期 | 年份 | 用途 |
| --- | --- | --- |
| 预热 | 2011—2012 | 正常前向计算，不率定、不评估 |
| 第一阶段率定 | 2013—2017 | 保存第一阶段参数诊断；参与最终率定 |
| 桥接 | 2018 | 正常计算产水，缺水账不补零、不插值，不率定、不评估 |
| 第二阶段率定 | 2019—2021 | 与第一阶段合并率定最终参数 |
| 正式验证 | 2022—2024 | 参数冻结后计算，禁止进入优化、参数选择及停止条件 |

用户已确认：最终参数使用两阶段合并的八个年份，不是仅在第二阶段重新率定。
2014 年兰州—头道拐库容变化仍缺失，影响头道拐及以下五站；该年贵得、兰州仍可率定。
预计每套最终率定使用 51 个有效站年，正式验证使用 21 个有效站年。

本次模型为七区年尺度 AWY（reach7），非月模型。AWY 没有跨年土壤／积雪状态；
因此“预热”在此是统一协议中正常运行而不计分的年份，不能声称初始化了年模型储水状态。
若后续对月模型实施相同协议，需连续积分 2011—2024 状态，不能从 2019 重新初始化。
2022、2023 已被历史开发查看；虽严格排除于本次率定，仍不是研究全过程从未见过的盲测年。2024 是新增年份。

## 2. 数据路径与气象完整性

新工作流所有数据文件、已对齐栅格、输出根目录、下载 URL／范围及年份均从 YAML 读取；
相对路径按项目根目录解析，不依赖终端当前目录。命令行仅指定配方文件。
迁移数据时改 YAML，不改 Python 中的文件名。已有历史脚本为旧快照复现代码，不是当前入口，
其旧年份／文件约定不应混入本实验；部分旧原始表已由用户新表替换，历史结果仍保留，但不能原样重跑。

- 主水账：实测年径流、地表耗水、库容变化三张新表，单位亿 m³。
- 地下水耗水、分区降水表保留并记录来源，未自动叠加到地表账户或代替栅格降水。
- TerraClimate **V1.1** 的 `ppt/pet` 覆盖 2011—2024；补下载 2011、2012、2024，其余复用已下载的同版本 NetCDF。
- 每份文件校验 SHA256、版本、单位、恰好 12 个对应年月；解码一次后相加成年 mm，再双线性对齐。
- 新统一年度栅格在 `project/comparison_2011_2024/climate/`；原始复用路径在 YAML 的 `climate.reuse`。
- `prepared.json` 记录 28 份变量—年份原始文件与年度栅格指纹；运行前检查配方及缓存指纹。缺月份／缺文件会报错，不静默跳年。
- 不混合旧 GEE PET 与新 V1.1 气候，不额外使用 TerraClimate 自带径流替代模型预测。

## 3. 三类产品和九种组合

A＝精细地类，B＝Copernicus，C＝ESA WorldCover v200。三者同气候、土壤、250 m 等积网格、
闭流域剔除及湖泊掩膜。WorldCover 使用最近邻分类重采样；v200 对应 2021 年产品，静态图不代表逐年土地变化。
实际本地 WorldCover 文件为 EPSG:4326、26564×11522 像元、约 0.000898315° 网格，
并非官方原生 10 m 网格；不能因配套表名带 `10m` 就把本地输入当成 10 m。
统一湖泊覆盖更改 WorldCover 的 15,240 个 250 m 像元（952.5 km²），没有用湖泊填补 NoData。
其他地类图也按已有静态图使用，图源年代和分类细度差异属于比较限制。

WorldCover 粗类参数沿用 Copernicus 对应功能类先验，林地映射 mixed-tree；
没有将其粗耕地擅自识别为精细双季作物。精细图原有双季作物 Kc 仍按当年 PET 加权。
因此比较的是“地类产品及其固定属性映射”整体，不是只改变空间分辨率。
类别映射写在 YAML。95 红树林未假定为其他地类，若在计算范围出现将以未定义类别报错。

| 最终参数来源 | 使用精细图 | 使用 Copernicus 图 | 使用 WorldCover 图 |
| --- | --- | --- | --- |
| 精细图率定参数 | A×A | A×B | A×C |
| Copernicus 率定参数 | B×A | B×B | B×C |
| WorldCover 率定参数 | C×A | C×B | C×C |

行内只更换地类产品，固定七个 Z、全局植被 Kc 乘数和兰州—头道拐净损失 L；
不为交叉单元重新优化。九个单元使用完全相同的有效站年。
三套率定均沿用相同边界、三个起点、目标函数与优化预算；最终参数文件先写完再做验证前向计算。
目标为有效率定站年的平均相对平方误差；不按验证误差挑起点、加参数或调整先验。
第一阶段参数仅作诊断，不拿来增加／择优替换九个最终组合。

加速沿用分区—地类分层抽样及解析导数；最终预测使用官方 AWY `fractp_op` 在全部有效像元计算，
并核验抽样与全像元差异不超过有效观测的 1%。每产品一次栅格读取同时计算三套参数。
默认双进程、每进程单线程，内存预算 24 GiB。不是完整 `InVEST execute` 工作目录，而是官方年产水内核与已有汇水分区的体积累计。

## 4. 径流口径与输出字段

条件径流＝累计 AWY 产水 − 已率定的指定区间净损失 − 累计地表耗水 − 累计库容变化。
它不是全面天然化／调度模型；未自动加入地下水耗水，也未虚构取水和回归水。

水账支持七站：贵得、兰州、头道拐、龙门、三门峡、花园口、利津。
用户已确认本轮维持七站径流评估，另列全部十一站产水，不增加账户分配假设。
唐乃亥、下河沿、石嘴山、高村缺匹配的细分管理账户，本次输出其产水量但不伪装成已修正径流；
若要十一站均评估，必须另行明确区间水账分配假设，不能暗中按面积分摊。
“龙羊峡以上”对贵得、“花园口以下”对利津仍是历史边界近似。
2018 年七站有产水计算值，但因水账缺失，管理径流预测为空；不能把未扣耗水的产水填入径流栏。

每次执行在 `experiments/landcover_cross/<UTC时间戳>/` 新建目录，不覆盖旧结果：

| 文件 | 内容 |
| --- | --- |
| `protocol.json`、`manifest.json` | 执行配方快照、数据指纹和时期规则 |
| `accounts.csv` | 14 年七站观测、水账及账户可用性 |
| `parameters_<product>.json` | 第一阶段诊断与两阶段合并最终参数、实际率定年份／样本数 |
| `tables_<product>.json`、`rotation_fine.csv` | 固定属性表、逐年双季作物 Kc |
| `predictions.csv` | 九组合×14 年×7 站＝882 行，含预测、观测、产水、修正量、误差、是否计分及排除原因 |
| `metrics.csv` | 各年全站 RMSE；每站各时期及全站各时期 RMSE，共 414 行 |
| `awy_all_stations.csv` | 九组合×14 年×11 站＝1386 行累计产水，不冒充管理径流 |
| `quadrature_<product>.json` | 三参数来源下抽样与全像元最大相对差异 |
| `summary.json` | 仅全部任务和核验完成后生成，含执行状态、资源使用 |
| `pairs/*.csv`、`validation_matrix.csv`、`report.md` | 汇总器复核后导出的九份独立组合、验证矩阵及可读报告 |

`parameter_source` 是参数率定产品，`landcover` 是实际前向使用产品，不能颠倒。
`station_year_rmse` 对单个年度观测就是 `abs(predicted-observed)`，不应解读为年内月误差。
`metrics.csv` 中 `scope=year` 为该年所有有效站点，`station_period` 为单站跨年，`period` 为该期所有有效站年。
RMSE＝sqrt(mean((预测−观测)²))，单位亿 m³；相对 RMSE＝100×sqrt(mean(((预测−观测)/观测)²))。
预热、桥接及缺水账站年 `scored=False`，误差／RMSE 留空，汇总样本数为零时也留空而非零。

## 5. 执行

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 python scripts/prepare_comparison.py --config config/landcover_comparison.yaml
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 python scripts/run_landcover_comparison.py --config config/landcover_comparison.yaml
# 完成后把 RUN_ID 换成程序输出的时间戳目录名：
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 python scripts/report_landcover_comparison.py --config config/landcover_comparison.yaml --run RUN_ID
```

准备可复用已校验原始下载；同网格、同原始指纹且派生指纹未变时复用年度栅格，否则重新生成。
正式运行拒绝使用配方不匹配的缓存。
本轮通过核验的结果见下一节；保留初次未通过的数值精度检查记录。

初次 `20261010T181430_710893Z` 使用每分区 8192 抽样预算，精细图最大抽样／全像元差异为观测的 1.1785%，
超过 1% 容差，执行器报错退出，结果保留但不作为通过验收的正式交付。
之后三个产品统一提高到 32768／分区重新执行，未改容差、优化目标、参数边界或训练年。
这是数值积分精度修正，不是按正式验证的好坏重新选参数方案。

完成日期：2026-10-11（香港时间）。通过版本目录：
[`20261010T182322_304737Z`](../experiments/landcover_cross/20261010T182322_304737Z/report.md)，目录名使用 UTC。

- [414 行逐年、逐站跨年及各时期指标](../experiments/landcover_cross/20261010T182322_304737Z/metrics.csv)
- [九份独立组合 CSV](../experiments/landcover_cross/20261010T182322_304737Z/pairs)
- [1386 行十一站累计产水](../experiments/landcover_cross/20261010T182322_304737Z/awy_all_stations.csv)

三套最终参数均使用 51 个有效率定站年，第一阶段诊断为 30 个；每个验证单元均为 21 个站年。
汇总器重新从预测值核算 RMSE，与原汇总一致，检查全部九组合和预热／桥接排除规则。

**2022—2024 整体验证 RMSE（亿 m³）**，行固定参数来源，列更换实际地类：

| 参数来源 \ 使用地类 | 精细 | Copernicus | WorldCover |
| --- | ---: | ---: | ---: |
| 精细率定参数 | 37.728 | 58.599 | 70.267 |
| Copernicus 率定参数 | 35.482 | 30.659 | 37.349 |
| WorldCover 率定参数 | 37.228 | 27.367 | 30.020 |

相同单元的 **相对 RMSE（%）**：

| 参数来源 \ 使用地类 | 精细 | Copernicus | WorldCover |
| --- | ---: | ---: | ---: |
| 精细率定参数 | 15.626 | 23.314 | 27.680 |
| Copernicus 率定参数 | 15.605 | 13.734 | 16.416 |
| WorldCover 率定参数 | 15.446 | 11.970 | 13.540 |

本次排序明显依赖参数来源：固定精细图率定参数时精细图较好，固定另外两套参数时 Copernicus 较好。
不能从三个分别率定的对角结果，或挑一行，宣布精细图普遍更优；也不能把事后最小的验证单元当作预先选定模型。
结果描述限于现有静态图／固定属性映射、给定水账和三年验证，2022、2023 的历史开发使用限制仍保留。
三套最终 Kc 乘数均触及 2.0 上界；部分 Z 的可识别性较弱，不把参数值直接解释为唯一物理真值。

全像元／抽样最大差异（占观测百分比）：精细 0.546%、Copernicus 0.221%、WorldCover 0.246%，
九组合全部低于预设 1%。通过版本率定约 248.4 秒、全像元前向计算约 298.9 秒，合计约 9.1 分钟；
峰值进程树内存约 3.46 GiB，不含准备下载及初次未通过试跑。
全量回归测试 **135 项通过**；Ruff 检查通过，122 个 Python 文件格式检查通过。
