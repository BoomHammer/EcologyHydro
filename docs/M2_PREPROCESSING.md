# M2 预处理与缓存

2026-10-09。入口已实现，使用真实数据完成裁剪、年度气候汇总、空间对齐、土壤参数派生、干流匹配、汇水区划分和质量诊断。验收实测结果见 [M2 验收记录](M2_ACCEPTANCE.md)。这里的“可供试算”不代表生物物理参数已经本地验证，也不代表完成 M3 的 InVEST 全流域性能验收。

## 运行

在项目根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 python -m ecologyhydro preprocess

# 按需执行；通常直接重跑上面的完整命令，缓存会自动跳过未改变的任务。
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 python -m ecologyhydro preprocess --stages static landcover climate
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 python -m ecologyhydro preprocess --stages routing quality
```

工程配置为 `config.yaml`，数据与处理配方为 `config/m2.yaml`。`--recipe` 可以使用另一份配方。年份读取 `study.calibration_years` 和 `study.validation_years`；降水方案诊断只使用校准年份。入口限制进程树内存及总时长，限值来自 `resources`；日志和峰值内存报告位于 `project/logs/`。超限终止不是成功验收。

原始数据不覆盖。结果索引为 `project/cache/m2/latest.json`，每次成功执行另存 `project/cache/m2/runs/`。从索引读取路径，不在后续代码中硬编码某个哈希目录。原始 AWY `inputs` 仍不指向任意年份，M3 应按年、地类方案和索引选择输入。

## 公共网格和裁剪

- 固定参考范围：`data/LCLU/Copernicus_Landcover_100m.tif` 的外包矩形。它只决定公共空间范围，像元类别内容不参与土壤、DEM 和气候缓存键。
- 投影：WGS84 Albers 等积投影，中央经线 105°，标准纬线 25°/47°，纬度原点 0°；面积按等积网格真实平方米计算，不使用 EPSG:3857 的名义像元面积。
- 当前试算分辨率 250 m。精细分类源像元为 0.00225°，约数百米；250 m 用于控制上采样和单机计算成本，不声称优于其他分辨率。后续 100/250/500 m 敏感性需独立运行和评价。
- 原点按 250 m 整倍数向外对齐。两套地类最近邻重采样，输出有符号整数；DEM、土壤连续属性及年度气候使用双线性插值。原始精细分类 0 不重编码为地类，也不添加物理参数；在质量检查中作为未定义类别报告。
- 土壤先按外包范围选择完整原生像元窗口，全球 BIL 不整幅加载。原始文件缺失 CRS；依据用户确认的 HWSD2 产品，派生副本明确采用 WGS84 地理坐标这一记录在案的假设，不修改原文件。
- CMFD 裁剪保留全部 888 个月和文件内全部变量、单位、日历、打包属性及缺失值；每侧保留一个原生网格支持插值。边缘因此可能稍超出参考矩形，并非改变最终公共网格。按月读取，避免加载完整时序。
- 降水年度值为月平均 `kg m-2 s-1 × 当月秒数` 的十二个月之和，闰年按实际月长。prec 与 bcpr 分开，不相加。缺月、重复月、意外单位和不支持的日历直接报错；任一月份缺失的像元不以剩余月份凑全年。
- TerraClimate PET：原始值乘 0.1 后逐月累加为 mm/年，不再乘天数；保留数值 0，不依据 0 自动判缺失。
- 首先在原生粗网格汇总年度气候，然后只重投影年度结果。质量阶段比较同一汇水范围的原生面积加权水量与对齐后水量；源网格边缘和覆盖比例计算仍是数值近似，报告其方法。

## 土壤和地类参数

`HWSD2_SMU` 从原始 MDB 导出并缓存。按 `HWSD2_SMU_ID` 关联；不能直接将土壤编码作为模型属性。

当前土壤试算采用单元表代表值 `AWC(mm/m) / 1000` 作为 PAWC。没有重复乘粗颗粒校正，也没有混用层表的 `AWC(mm)`。这是单元代表属性路线，不是已经完成了七土层、各组分的重新加权。AWC 的零值保留并报告，不能简单改成正的常数。

`ROOT_DEPTH` 为等级。配方明确登记 1/2/3/4 对应 1500/750/300/50 mm：将深层上限暂截在 HWSD2 的 200 cm 表征范围，在相应区间取代表值。这是试算代理值，**不是数据库提供的实测限制层深度**，也不是把类别编码直接当毫米。需要在后续对土层有效深度及敏感性作科学核验。

生物物理输入生成于独立 `landcover/biophysical/` 缓存，包含 AWY 3.20.2 的 `lucode,lulc_veg,root_depth,kc` 和来源、状态列。`config/biophysical_priors.yaml` 是公开可审查的**工程试算参数**：相同功能组在两套地类中使用相同值，不给精细分类预设更有利的参数。所有数值的来源是本项目试算先验，并非已从文献提取的黄河流域年度 Kc；不能据此开展正式精度比较。湿地依照 AWY 的接口设置 `lulc_veg=0`；非植被类根深为不参与计算的正占位值。大棚、苔藓、疏林等功能组近似尤其需要后续细化。

参数表完整性、数值范围、所有源类别映射均检查，0 和 255 禁止赋值。正式率定/实验前须为年度 Kc 和有效根深补齐研究区适用依据或预先登记的参数估计方案。程序的 `formal_experiment_ready` 保持 false，不将可运行的工程参数误报为科学验收。

参数含义依据 [InVEST AWY](https://storage.googleapis.com/releases.naturalcapitalproject.org/invest-userguide/latest/en/annual_water_yield.html)、[FAO HWSD2](https://www.fao.org/land-water/resources/tools/databases/hwsd/en)。[FAO-56 表 22](https://www.fao.org/4/x0490e/x0490e0e.htm)提供作物根深范围，但不能直接替代所有本地生态类型的有效根深或全年 Kc。上述文献不被用作试算表具体数值的虚假出处。

## 干流、汇水区与基础分区

1. 读取 HydroRIVERS 的下游连接、主河流编号、上游面积和内流标记。选择最大外流网络的终点，沿每个汇合处上游面积最大的支路回溯干流，再用 11 站顺序及距离核验。`MAIN_RIV` 相同表示同一河网，不能把整张河网当作干流。歧义、缺段或站序错误报错。
2. 将原始 CGCS2000 测站坐标转换至分析投影，求干流线段上的最近点；不局限于顶点，不搜索支流。保存原点、匹配点、河段编号、距离和 SVG 图。CGCS2000/WGS84 的近似坐标操作明确记录。
3. 单纯填洼的首轮实测存在多个测站不连通，未作为正式分区发布。修正方案在已核验的主干河道像元降低 5 m，保留河口和 HydroRIVERS 已明确标识的 77 个内流终点为排水终点，再执行填洼及 D8 流向。河道离散路径去掉小于网格尺度的回环，并按已核验河网明确约束干流 D8 连接。这样可以跨越 DSM/粗河网不一致和坝体影响；不能解释为测得的河床高程。
4. 输出修正像元数、原始沿河逆坡步长、修改的流向数量和内流终点。最大逆坡等诊断不隐藏；该修正是一项可复现的建模假设，仍需在 M3/后续敏感性中评价。不按参考面积修正 DEM 或人为圈定内流区。
5. 出口仅在匹配点 2 km 范围内、与已识别干流相交的像元上寻找，优先高汇流累积值，记录二次位移。划分全部上游区域后检查每级包含上一站；不嵌套时保留失败诊断，不发布分区索引。
6. 嵌套通过后，按下游先写、上游覆盖生成互不重叠的 `zones.tif`，同时输出 `zones.gpkg` 和 `zone_station.csv`。每个分区在同一站汇总中只有一次。各像元均为 0.0625 km²；水量按实际分区面积计算。
7. 质量检查分别针对近似边界和实际汇水区。检查 DEM 有效域边缘相邻像元、共同有效区域、未定义地类和 PET 零值。共同掩膜只是质量结果，不能通过删掉缺失像元继续宣称完整上游产水。

HydroRIVERS 字段和网络含义参见[官方技术文档](https://data.hydrosheds.org/file/technical-documentation/HydroRIVERS_TechDoc_v10.pdf)。现有 shp 仍只作为近似参考，不用于硬裁切汇流区，其未指定测地基准的近似转换记录在报告中。未在 HydroRIVERS 中识别的内流区域影响仍未量化。

## 降水选择

按贵得、兰州、头道拐、龙门、三门峡、花园口端点建立前六个统计区间的代理范围，仅比较校准期降水体积。使用区间相对体积偏差绝对值的平均值选择工程试算候选，保存 prec 和 bcpr 两套完整结果。面积差异不通过比例缩放消除；不能把该比较称为严格同边界验证。花园口至利津不等同于“花园口以下”，不参与候选排序；内流区行也不参与干流累计。2023 的降水和径流观测不参与该选择。

## 缓存约定

| 缓存 | 内容 | 何时需要重建 |
| --- | --- | --- |
| `grid` | 投影、范围、原点、分辨率 | 网格或实现变化 |
| `static` | 土壤裁剪、MDB 导出、PAWC/限制层深度原生结果 | 土壤输入、参数转换变化 |
| `climate/crop` | 原生月气候空间子集，保留全部日期 | 相应变量源文件或范围变化 |
| `climate/annual` | 分变量、分年份的年度原生栅格 | 月数据或年度算法变化 |
| `aligned` | 每一项输入的公共网格结果 | 该输入或网格/重采样方法变化 |
| `landcover/biophysical` | 两套地类试算参数表 | 类别表或参数先验变化 |
| `routing` | 干流、站点、修正 DEM、填洼、流向、累积、出口、汇水区、分区索引 | DEM、河网、站点、网格或水文处理变化 |
| `quality` | 边界掩膜、共同有效掩膜、覆盖/类别/重采样/降水报告 | 相应输入或诊断方法变化 |

每个产物有 `manifest.json`，包含输入 SHA256、参数、实现文件指纹、GDAL/NumPy/netCDF4/pygeoprocessing 版本、输出校验值和耗时。临时目录完成后才发布，失败产物不作为缓存使用。命中时验证输出大小、时间和 SHA256；被外部修改的缓存会报错，不静默继续。源文件在处理期间发生变化也会拒绝发布。

更换地类或气候后，使用完整命令让依赖键自动判定；只要公共网格、DEM、河网、站点和土壤处理未变，静态及水文缓存可复用。派生的模型结果不能只按文件名识别数据版本。实现文件改变时相应模块缓存保守失效；旧目录保留作追溯，不自动清理。

M2 加速主要来自空间裁剪、年度先聚合、窗口扫描及 GDAL/pygeoprocessing 的本地编译算法。当前流水线串行调度以控制磁盘和内存竞争，不按逻辑线程数启动大量任务。独立模型任务的并发基准和正式 12 小时模拟验收在 M3 完成。
